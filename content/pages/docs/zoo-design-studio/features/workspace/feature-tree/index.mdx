The Feature Tree organizes the current model by body. Each [body row](/docs/zoo-design-studio/features/workspace/body-pane)
has a body icon, selection and visibility controls, and an arrow to expand its contributing
features. Features remain in execution order within each body. Parameters and features without
a body association stay at the root.

Shared features can appear under more than one body. Editing a shared feature updates all bodies
that depend on it. Collapsing a body only hides its feature rows; use its eye control to hide the
geometry.

## What You Can Do

- Expand individual bodies to inspect their feature histories and grouped operations.
- Select, hide, show, or delete a body directly from its row.
- Select operations and jump to the corresponding KCL source.
- Double-click a supported modeling operation to edit its parameters in a dialog. Existing
  geometry selections are read-only; edit those references in KCL when needed, or delete the
  operation and recreate it.
- Use context menu actions such as `Edit`, `Delete`, `Translate`, `Rotate`, `Scale`, `Clone`, and
  `Set Appearance` when the operation type supports them.
- Export supported sketch operations to DXF from the context menu.

## What You Cannot Do

- Edit every operation from the tree. Some operation types are view-only or partially supported.
- Edit user-defined function or module operations from the tree. Edit those in code instead.
- Rely on tree-based editing for every sketch-on-face or offset-plane workflow. Some of those still
  require scene-based editing.

## Key Differences in This Area

- Tree items stay linked to modeling dialogs and KCL source ranges.
- Editing coverage is intentionally partial, so some workflows remain code- or scene-driven.
