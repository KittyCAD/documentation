The Feature Tree organizes the model as imported parts, bodies, and their contributing features.
Expand a [body](/docs/zoo-design-studio/features/workspace/body-pane) to see its sketches, regions,
creation features, and later modifications in execution order. Consumed Boolean inputs remain in
the resulting body's history. Shared features can appear under several bodies as references to the
same feature.

Named modeling features show their operation type beside the KCL variable name. This distinguishes
features such as an offset plane and a sketch that share a name.

Imported parts and subassemblies contain their own bodies. Bodies created directly in an assembly
remain at its top level, alongside file-level parameters and unresolved features. 3D patterns and
instance edits stay under the source body; individual instances remain selectable in the Scene.

Parts, bodies, and feature groups start collapsed. Their disclosure arrows control the tree only;
they do not hide geometry. Expansion choices survive sketch editing, rebuilds, and closing and
reopening a parent branch, and are scoped to the current file.

## What You Can Do

- Inspect body histories and grouped operations.
- Click a body row to select that body, or use its eye control to hide or show it.
- Select operations and jump to the corresponding KCL source.
- Double-click a supported modeling operation to edit its parameters in a dialog. Existing
  geometry selections are read-only; edit those references in KCL when needed, or delete the
  operation and recreate it.
- Use context menu actions such as `Edit`, `Delete`, `Translate`, `Rotate`, `Scale`, `Clone`, and
  `Set Appearance` when the operation type supports them.
- Export supported sketch operations to DXF from the context menu.

## What You Cannot Do

- Edit every operation from the tree. Some operation types are view-only or partially supported.
- Edit user-defined function or module operations from the tree. Edit those in code instead.
- Rely on tree-based editing for every sketch-on-face or offset-plane workflow. Some of those still
  require scene-based editing.

## Key Differences in This Area

- Tree items stay linked to modeling dialogs and KCL source ranges.
- Editing coverage is intentionally partial, so some workflows remain code- or scene-driven.
