The Code Editor is the KCL source panel for the active model.
It also opens project text files selected in the
[File Explorer](/docs/zoo-design-studio/features/workspace/file-explorer#open-text-files).

## What You Can Do

- Edit the model directly in KCL.
- Format code, copy code, and open KCL docs from the pane menu.
- Use diagnostics, lint markers, and syntax-aware editor behavior.
- Use undo and redo within the app's editing workflow.
- Edit UTF-8 project text files up to 1 MiB with automatic saving. Markdown files have syntax
  highlighting; other non-KCL text files use plain text editing.

## Pause and Execute KCL

Select **Pause** above the KCL editor to stop automatically executing each code change. Your
edits continue to save, and the last rendered model remains visible. You can still rotate,
zoom, and pan the model.

After you change code while paused, the feature tree and modeling tools become unavailable.
The editor explains that you need to execute the pending changes. Select **Execute** to render
them once while keeping automatic execution paused, or select **Resume** to render pending
changes and turn automatic execution back on.

These controls use the **Automatically Render** editor setting. Pausing execution does not
cancel a model that is already running. The controls apply to KCL; opening a project text file
does not show them or execute KCL.

## What You Cannot Do

- Treat point-and-click edits as separate from code. In Zoo Design Studio, KCL remains the source
  of truth.
- Rely on clipboard features if browser permissions block clipboard access.

## Key Differences in This Area

- KCL source is the model authority, so graphical edits and code edits stay linked.
