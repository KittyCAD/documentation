A project library is just a way of grouping projects in Zoo Design Studio. The ZDS home page is organized into libraries so that you can separate out different groups of your work. You can think of project libraries like folders containing projects, although in reality they are just a *view* into any grouping of projects, which makes them more powerful in a way we'll explain shortly.

On desktop, there are two kinds of libraries available today:
- **Directory** libraries are views into a folder on your computer. When you open a project from a directory library, you are literally editing your own files. This is good, because we think you should own your files!
- **Cloud** libraries show projects saved to your Zoo account. Personal Cloud projects are available when you sign in on another device. Opening a cloud project loads its files into memory, and edits save directly to the cloud. Use a Directory library when you want files stored in a folder on your computer.
- We are experimenting with more kinds of libraries, but one that will come soon is a Recents library type, which will simply be a way of grouping the projects you've opened most recently. If you have other ways of sourcing and grouping projects that you would like to see, reach out to us on our [support forum](https://community.zoo.dev/).

When you open Zoo Design Studio as a desktop app, you should see one directory library and one cloud library available to you right away.

## Managing libraries

You can manage your libraries in your user settings. Libraries can be reordered, renamed, created, or deleted as you see fit. Try out creating a second Directory-type library to separate out work for under a client, or for a product line you're building out.



## Recovering a Failed Local Save

If saving a KCL file in a Directory library fails, the project header shows `Save failed. Retry` and your edits remain in the editor. Restore access to the storage location or free disk space, then click the button to retry. Keep the project open until saving finishes.

## Create a Project in a Library

For every new project you create, it will be placed in one of your libraries. You can change which library it will be added to by clicking the `Library` label in the command palette and choosing a new library to place the project within.

### Clone Projects Into Another Library

Use **Clone project** in the Command Bar or project menu, or **Clone to another library** in a Home project card's context menu. Choose the destination library and review the command.

Cloning creates an independent project and keeps the original. For example, cloning a Directory project into Personal Cloud creates a new cloud project from its saved files. Subsequent edits to either project do not update the other. Each clone gets a new project identity and starts without the original project's saved Zookeeper conversation.

You can clone between Directory libraries or between a Directory library and Personal Cloud. If destination creation fails, the original remains available. Edits made to the original while a cloud upload is pending stay with the original.

### Delete a Project

Deleting from a Directory library removes the local project folder. Deleting from a Cloud library deletes the cloud project. Historical local copies from older versions of Zoo Design Studio are separate files and remain on your device. Deleting a cloud project also deletes any Aquarium publication backed by that project.

Read the confirmation dialog before deleting. Project deletion is permanent and has no undo.

### Delete Files and Folders

You can undo file and folder deletions while they remain in the current editor's undo history. For local projects, deleted contents are kept only in memory for that editing session. Closing or reloading the app discards them.

For cloud projects, Undo retrieves the deleted contents from the saved cloud revision without rolling back other project changes. For both kinds of project, Undo will not overwrite a different entry created at the same path, and Redo will not delete restored contents that have since changed.

This editing history is temporary; reloading or switching files can make the deletion unavailable to Undo. Deleting an entire cloud project remains permanent.

### Desktop and Browser Differences

On desktop, Zoo Design Studio can show Directory and Cloud libraries side by side. This lets you keep local-only work, Git-based work, and cloud-backed work in one Home view.

In the browser, Zoo Design Studio only allows Cloud libraries.
