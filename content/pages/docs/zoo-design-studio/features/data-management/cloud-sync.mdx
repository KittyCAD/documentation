Projects in Personal Cloud save directly to your Zoo account. Opening a cloud project loads its files into memory; edits save to Zoo as you work. Cloud projects have no working folder on your computer.

In the desktop app, use a [Local library](/docs/zoo-design-studio/features/data-management/project-libraries) to keep projects as local files. The browser app supports Cloud libraries only.

## Get started

Create a project in Personal Cloud, or use **Duplicate project** to copy an existing Local project into it. Duplicating keeps the original project. Later edits to either project do not update the other.

To continue on another device:

1. Wait for saving to finish on the device where you last edited the project.
2. Sign in with the same Zoo account on the other device or in a browser.
3. Open the project from Personal Cloud.

## Saving and connection failures

The save indicator shows `Saving...` while a save is pending. If it fails, your edits remain in memory and the indicator shows `Save failed. Retry`. Restore your connection and retry the save. Keep the project open until saving finishes: closing or reloading the app discards edits that have not reached the cloud.

Cloud projects are read-only while your device is offline. You can view files in an already-open project, but cannot edit their contents or create, rename, or delete files. Editing becomes available again when your connection returns. Local projects remain editable and save to disk while offline.

## Changes from another device

Cloud storage is not a live collaboration session. Wait for saving to finish before switching devices or editing the same project elsewhere.

Zoo Design Studio checks for changes to an open cloud project and can load the newer cloud version. If a save encounters a revision conflict, the app reloads the current cloud snapshot. Differing cloud contents can replace unsaved edits; a notification explains when this happens. Keep only one editing session active when you need to avoid competing changes.

## Zookeeper changes

Zookeeper reads and saves cloud project files directly through Zoo. Zoo Design Studio refreshes the open project after Zookeeper changes cloud files, including additions, moves, and deletions. Local projects continue to use files from their Local library.

## Existing local cloud copies

Folders and browser storage created by earlier versions of Cloud Sync are left untouched. They are no longer working copies of the cloud project, and edits in them are not automatically uploaded. Keep any old copy containing work you still need; files in an existing desktop folder remain available for manual recovery.

## Keep a local copy

In the desktop app, use **Duplicate project** to create an independent copy in a Local library. Edits to that copy save to its local folder. The original remains in Personal Cloud unless you delete it separately.

See [Project Libraries](/docs/zoo-design-studio/features/data-management/project-libraries#duplicate-projects) for the duplication workflow.

## Publish to Aquarium

[Aquarium](/docs/zoo-design-studio/features/data-management/aquarium) publishes a submitted version of a cloud project after review. Saving a project to Personal Cloud does not publish it.

If you publish a Local project, Zoo Design Studio creates a cloud duplicate and keeps the original folder. Later edits to the cloud project do not automatically update its Aquarium submission; use the Publish dialog to submit an updated version.

## Common questions

### How do I know where a project is saved?

Check its library on Home. Projects in Personal Cloud save to your Zoo account. Projects in a Local library save to that folder on your computer.

### How much cloud storage do I get?

Storage is limited to what we consider fair use for Free users. Paid subscription tiers all get unlimited storage.

### Are cloud projects private?

Yes. Today, unpublished Personal Cloud projects remain private in your Zoo account on both Free and paid plans. Changing or canceling a subscription does not publish or remove them; after a downgrade, the projects remain private in the same account on the Free plan.

Zoo may introduce a semi-public storage state for Free-plan projects in the future. That behavior, including any associated data-use or model-training policy, is not active today. Zoo will update its website and documentation before enabling a different visibility or data-use policy.

### Will clearing my browser cache delete my cloud projects?

No. Clearing browser cache or site storage does not delete saved projects from Personal Cloud. Reloading or closing an open project discards unsaved edits held in memory, so wait for saving to finish first.

### Can I work offline?

You need a connection to open a cloud project and save changes. An already-open cloud project becomes read-only offline. If a save failed when the connection dropped, keep the project open, restore the connection, and retry it before closing or reloading.

Use a Local library when you need files available locally. Modeling execution may still require a connection, depending on your renderer and workflow.

### Is cloud storage version control or a backup?

Cloud storage keeps your saved project available through your Zoo account. It does not provide Git-style history, branches, or code review. Use [version control](/docs/zoo-design-studio/features/data-management/version-control) or another backup system when you need recovery outside the current cloud version.

### What does this "shared history" warning mean?

This warning appears when project folders on your device share the same local project ID, usually
because they were copied outside Zoo Design Studio. These copies can share Zookeeper history.

Right-click a project card and choose **Separate project copies**. Choose which copy keeps the
shared history, or start fresh for all copies. Each remaining copy gets a new project ID and no
saved conversation reference. This does not delete the conversations stored by Zoo.
