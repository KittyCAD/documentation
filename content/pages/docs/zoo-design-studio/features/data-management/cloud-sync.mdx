Personal Cloud saves projects to your Zoo account so you can open them from another device. The browser app uses cloud storage. The desktop app also supports Directory libraries for projects stored on your computer.

Opening a cloud project downloads its files into memory. Edits save directly to the cloud; Zoo Design Studio does not maintain a disk or browser-storage mirror of the project. Keep the project open while a save is pending or has failed.

## Getting Started
When you open the desktop Zoo Design Studio app for the first time, you will see two project libraries where you can create projects. One of those is called "Personal Cloud", and any projects you put in there will be synced across any device you sign in from.

The status bar shows `Saving...` while a cloud save is pending and `Save failed. Retry` if it fails. Wait until saving finishes before closing the project or switching devices.

## Common Workflows

### Use A Project On Another Device
1. Create the project within the Personal Cloud library or clone an existing project into it.
2. Keep the project open and wait until `Saving...` disappears. If `Save failed. Retry` appears, resolve the failure and retry before switching devices.
3. Sign in to Zoo Design Studio with the same account on the other device or in a browser.
4. Open the project from Personal Cloud.

### Updates From Another Device

While a cloud project is open, Zoo Design Studio checks for changes from other clients. Remote edits and deletions appear automatically when there are no pending edits or active Zookeeper operations. Checks pause while the app is hidden or offline and resume when you return. Updates also refresh geometry in a sketch that is already open. If an update deletes that sketch, Zoo Design Studio exits sketch mode. When there are no pending saves, starting a new shape checks for newer saved contents. New geometry appears immediately. As with code edits, quick sketch operations share a save debounce window: after you pause, the latest committed edits save in the background. An upload already in progress finishes before the next save begins. Pointer movement continues to update the shape and code preview without waiting for storage. Circles show their code while you size the radius; canceling removes the unfinished circle without saving it.

Cloud projects are read-only while your device is offline. You can view files, but cannot edit their contents or create, rename, or delete files. Editing becomes available again when your connection returns. Edits caught by a disconnection stay in memory and saving resumes after reconnection. Local files remain editable and continue saving to disk while offline.

### Save Failures and Conflicts

While a cloud save is pending, the project header shows `Saving...`. If the save fails, your edits remain in memory and the header shows `Save failed. Retry`. Restore your connection and click that button to try again. Keep the project open until saving finishes.

If the cloud project has changed since your last acknowledged save, Zoo Design Studio reloads the current cloud snapshot. The cloud version is the source of truth: differing cloud contents replace your editor contents, and pending edits based on the previous snapshot are canceled. A notification explains when the cloud version replaces unsaved edits. Further edits save against the newly loaded cloud revision.

Unsaved cloud edits remain only in memory. Closing or reloading the app discards them and opens the current cloud version; an older local recovery draft cannot replace it. Keep the project open until saving finishes if you want to retry an unsaved edit.

A connection can fail after the server accepts a save but before the app receives its acknowledgement. Retrying may then encounter a revision conflict even though your contents reached the cloud. Zoo Design Studio compares the cloud snapshot with the rejected upload. If they match, it acknowledges that save and continues saving newer edits without replacing the editor. If they differ, it adopts the cloud snapshot.

### Stop Syncing

On desktop, use **Clone project** to create a project in a Directory library from the cloud project. Edits to the new project save to that local folder. The original cloud project remains in Personal Cloud; delete it separately if you no longer need it. See [Project Libraries](/docs/zoo-design-studio/features/data-management/project-libraries#clone-projects-into-another-library).

### Publish To Our Project Showcase 
Our public project showcase  [the Aquarium](/docs/zoo-design-studio/features/data-management/aquarium) uses cloud sync too!. Not all cloud synced projects are published to the Aquarium, but all projects submitted to the Aquarium must be cloud synced, so when you submit a project for publication in ZDS we create a new project in Personal Cloud from your Directory project and keep the original folder.

1. Open the project and click the `Publish` button in the top-right.
2. Complete the Aquarium submission and submit it for review.
3. Wait for the publication status to become `Published`.
4. Share the public Aquarium URL.

## Common Questions

### How Do I Know Which Projects Are Saved to the Cloud?

Check the library that contains the project on Home. Only projects in `Personal Cloud` and other cloud-type project libraries are saved to your Zoo account. The library will have a cloud icon next to it.

### How Much Cloud Storage Do I Get?

Storage is limited to what we consider fair use for Free users. Paid subscription tiers all get unlimited storage.

### Are Cloud Projects Private?

Yes. Today, unpublished Personal Cloud projects remain private in your Zoo account on both Free and paid plans. Changing or canceling a subscription does not publish or remove them; after a downgrade, the projects remain private in the same account on the Free plan.

Zoo may introduce a semi-public storage state for Free-plan projects in the future. That behavior, including any associated data-use or model-training policy, is not active today. Zoo will update its website and documentation before enabling a different visibility or data-use policy.

### Will Clearing My Browser Cache Delete My Cloud Projects?

No. Clearing the browser's cached images and files does not delete projects from Personal Cloud. If you clear the **site data or site storage** for app.zoo.dev while pending work is still syncing, there is a chance that your changes may not be saved, but your project is safe in the cloud.

### Where Do My Files Live?

The saved project lives in Zoo's cloud storage. While it is open, the app holds its files and any pending edits in memory. Closing or reloading the app discards changes that have not reached the cloud.

To keep a project as files on your computer, clone it into a Directory library in the desktop app.

### Can I Work Offline?

Cloud projects need a connection to open and save. If your connection drops while a project is open, edits remain in memory. Keep it open, restore the connection, and retry any failed save before closing or reloading.

Use a Directory library for files you need to access on your computer without downloading them from Personal Cloud. Modeling execution still needs a connection to the engine.

### Can I Use Personal Cloud on Multiple Devices?

Wait for saving to finish on the first device before opening the project elsewhere. If another device changes the cloud revision before your save, Zoo Design Studio reloads the cloud snapshot. Differing cloud contents replace your editor contents, as described under [Save Failures and Conflicts](#save-failures-and-conflicts).

### Is Cloud Sync Version Control or a Backup?

No. Cloud Sync keeps the current project available through your Zoo account, but it does not provide Git-style history, branches, or code review. Use Git or another backup system when you need revision history or recovery outside the current synced project.

Development is underway for version control built on top of the Zoo Projects API that powers Cloud Sync, so stay tuned.

### What does this "shared history" warning mean?

This warning appears when project folders on your device share the same local project ID, usually
because they were copied outside Zoo Design Studio. These copies can share Zookeeper history.

Right-click a project card and choose **Separate project copies**. Choose which copy keeps the
shared history, or start fresh for all copies. Each remaining copy gets a new project ID and no
saved conversation reference. This does not delete the conversations stored by Zoo.
