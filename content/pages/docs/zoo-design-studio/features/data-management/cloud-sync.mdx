title: Cloud Projects

Personal Cloud stores projects in your Zoo account. Opening a cloud project loads its files into memory in Zoo Design Studio. Cloud projects do not create or update a project folder on your computer or in browser site storage.

Directory libraries on desktop continue to read and write your local files. See [Project Libraries](/docs/zoo-design-studio/features/data-management/project-libraries).

## Saving Changes

Cloud project changes are saved directly to Zoo. The top bar shows `Saving...` while a save is in progress. A save completes when the server acknowledges it.

If a save fails, your changes remain in memory and the top bar shows **Save failed. Retry**. Keep the app open and retry after restoring your connection. Closing the app, reloading the page, or losing the browser session can discard changes that the server has not acknowledged. Export a copy before closing if a save cannot complete.

Opening a cloud project requires a connection. An already-open project can retain edits in memory during a connection failure, but those edits are not durably saved until the server accepts them.

## Zookeeper Changes

Zookeeper reads cloud project files directly from Zoo. Cloud prompts and resumed conversations identify the project without uploading another copy of its files. Local projects still send their files with the prompt, and you can attach reference files to prompts for either project type.

Zookeeper saves cloud project changes directly to Zoo. Zoo Design Studio reloads the latest project files after cloud file operations and when the turn finishes, including added, moved, and deleted files. If Zookeeper removes the file you are viewing, the app opens the project's default file.

A refresh does not replace edits whose cloud save has failed. Resolve the failed save before refreshing so those edits remain protected.

## Using Multiple Devices

Wait for saving to finish before switching devices. Cloud projects are not live collaboration sessions. If another device has changed the project since you opened it, the server rejects a stale save rather than overwriting the newer version. Preserve your edits with an export before reloading the latest cloud version.

## Moving Projects

Use **Move project** to transfer a project between Personal Cloud and a Directory library. The destination is saved before the source is removed. Moving a cloud project into a Directory library removes the cloud project after the local files are written; this also removes any associated Aquarium publication.

Exporting a ZIP provides a separate downloadable copy without moving the project.

## Existing Local Cloud Copies

Folders and browser storage created by earlier versions of Cloud Sync are left untouched. Zoo Design Studio no longer reads, updates, syncs, or deletes those copies as part of cloud project storage. Unsynced edits in an old copy are not automatically uploaded or included when you open the cloud project.

Keep any old copy containing work you still need. Files in an existing desktop folder remain available for manual recovery.

## Privacy and Publication

Saving a project to Personal Cloud does not publish it to Aquarium. Publication is an explicit action that submits a snapshot for review. See [Aquarium](/docs/zoo-design-studio/features/data-management/aquarium).
