Cloud sync keeps Zoo Design Studio projects available through your Zoo account while preserving the
project files you work with locally.

The sync model follows the same project-library principles:

- Local reads and writes happen first.
- Project contents are ordinary files, including human-readable KCL and `project.toml`.
- Cloud sync runs in the background and uploads or downloads whole project snapshots.
- Sync failures do not remove local files or block local edits.

## How Cloud Sync Works

When cloud sync is enabled, Zoo Design Studio watches project file changes and queues cloud work in
the background. Creating, editing, renaming, and deleting project files still happens locally first.
The sync engine then reconciles those local changes with the Zoo cloud project.

Projects can appear in several cloud states:

| State | Meaning |
| --- | --- |
| `Cloud-only` | The project exists in Zoo cloud and has not been downloaded on this device yet. Opening it creates a local working copy. |
| `Syncing` | Zoo Design Studio is uploading or downloading project data. |
| `Synced` | Local files and the cloud project are up to date. |
| `Cloud sync pending` | Local changes are queued for upload. |
| `Cloud sync failed` | Sync could not complete and will be retried. |
| `Cloud sync blocked` | Zoo Design Studio can read the cloud project but cannot upload local changes, usually because the current account lacks write access. |
| `Conflicted` | Local and cloud data both changed since the last synced version and need manual resolution. |

## Start Syncing

To start syncing a local Directory project, move it to `Personal Cloud`:

1. Select `Move to library` from the Command Bar, the project menu in the top bar, or the project
   card context menu on Home.
2. Choose the local project.
3. Choose `Personal Cloud` as the destination library.
4. Confirm the move.

Zoo Design Studio moves the project into the cloud library, uploads it to your Zoo account, and keeps
a local working copy for normal editing.

Creating a project directly in `Personal Cloud` also starts it as a synced project. In the browser,
Personal Cloud is the only project library, so projects are cloud-backed by default.

## Stop Syncing

To make a synced project local-only, move it from `Personal Cloud` to a Directory library:

1. Select `Move to library` from the Command Bar, the project menu in the top bar, or the project
   card context menu on Home.
2. Choose the synced project.
3. Choose a Directory library as the destination.
4. Confirm the move.

Zoo Design Studio moves the project into the selected local library and stops cloud sync for that
project. Future edits happen only in the local Directory library unless you move the project back to
`Personal Cloud`.

## Identify Conflicts

A cloud sync conflict happens when the local project and the cloud project both changed after the
last synced version, and Zoo Design Studio cannot choose one without risking data loss.

When a conflict is detected:

- The project card on Home shows a `Cloud conflict` badge.
- The project breadcrumb can show a `Cloud conflict` badge while the project is open.
- The status bar shows `Cloud conflict`.
- The project menu shows `Inspect Conflicts`.

Zoo Design Studio keeps your current local project as the primary project. The cloud version is saved
locally as a separate conflict copy with a name like `project-name (cloud conflict
YYYYMMDDTHHMMSS)`.

## Resolve Conflicts

Open the conflict dialog from the project menu or from the cloud sync status UI.

The conflict dialog lists changed files and labels each file as:

- `Changed`, when local and cloud both have the file but with different contents.
- `Only local`, when the file exists only in the local project.
- `Only cloud`, when the file exists only in the saved cloud copy.

Text files, including `.kcl` and Markdown files, show a side-by-side diff when possible. Large,
binary, or non-UTF-8 files may show file metadata without an inline diff.

Choose one resolution:

- `Use local data` uploads the current local project to the cloud and removes the saved conflict
  copy.
- `Use cloud data` replaces the local project with the saved cloud version and resumes sync from
  that version.

If you need to combine both versions, manually copy or edit the files you want into the local
project first, then choose `Use local data`.
